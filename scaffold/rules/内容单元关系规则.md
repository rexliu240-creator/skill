# 内容单元关系规则

## 允许的关系类型（第一期只有 4 类）

| 类型 | 方向 | 含义 | 例 |
|---|---|---|---|
| 回应 | OPI/SOL → QST | 这个观点/方案回答了这个问题 | OPI001 回应 QST001 |
| 解释 | CON → QST/OPI | 这个概念帮助理解该问题或观点 | CON001 解释 QST001 |
| 证明 | CAS → OPI | 这个案例支撑该观点 | CAS001 证明 OPI001 |
| 冲突 | 任意 → 任意 | 两条内容在事实或主张上矛盾 | OPI002 冲突 OPI001 |

## 硬规则

1. 只允许上述 4 类，新关系类型必须先改本规则再使用
2. 关系的 target 必须是真实存在的单元 ID；目标缺失数必须为 0（generate-link-map.js 会校验）
3. 一条关系写在"发起方"单元里，不重复写在目标方
4. 冲突关系必须与去重流程联动：判为冲突的内容不合并，登记后保留两条

## 方向校验口诀

- 回应/解释/证明：从"交付物"指向"被交付的对象"
- 冲突：无严格方向，但建议从"更新的一方"指向"被挑战的一方"

## 常见错误

- 把"相关"当关系 → 相关不是关系类型，用主题地图聚合
- target 写文件名而不是 ID → 不行，必须用结构化 ID
- 双向重复登记 → 只登记一次，总览由脚本生成
