# 内容单元去重与版本规则

## 去重类型（第一期只有 4 类）

| 类型 | 判定 | 默认处理 |
|---|---|---|
| 完全重复 | 原文实质一致 | 合并：保留 ID 较小者，source_documents 合并 |
| 同义重复 | 同一论点/定义换表述 | 合并：保留表达更完整者 |
| 近似重复 | 相近但角度或条件不同 | 人工判断：合并或保留，须写明理由 |
| 重复讲述 | 同一话题在不同场景重新讲述 | 保留两条：建立 关系 或靠主题地图聚合 |

只有 完全重复 与 同义重复 默认合并；其余必须人工判断。

## 流程

1. 抽取新单元前，先用 keywords + 标题与现有单元比对
2. 疑似重复的写入去重候选（generate-duplicate-candidates.js 自动生成 + 人工补充）
3. 每条候选必须落一个明确结论：合并 / 保留 / 冲突，不允许"待定"长期堆积
4. 合并时：被合并单元 canonical 改为 false，其关系迁移到保留单元，其 source_documents 并入保留单元
5. 判为冲突的内容不合并，在双方登记 冲突 关系

## 版本规则

- 实质修改（定义、论点、事实、字段口径变化）→ version +1，并在文末 `## 修订记录` 写一行：日期 + 改了什么 + 为什么
- 错别字、格式调整不算实质修改，不动 version
- 不新建文件表示历史版本，历史交给 Git

## 失控信号（出现任一要停下复盘）

- 去重候选数量接近或超过单元总数的一半
- 同一对单元反复出现在候选里
- 合并后关系目标缺失数上升
